## Result variants, logs and streams

Succeeded outcome has exactly kind, first, second, logs, with kind=succeeded. first and second each have exactly sha256, bytes; bytes in1..268435456 and lowercase SHA256 syntax. Their bytes and digests must agree, but agreement of two claims alone is not proof: signer independently copies both real streams to exclusive private staging, recomputes each hash/size, compares the copied artifacts byte for byte, and qualifies source/recipe/native/audit boundaries before signing.

Refused outcome has exactly kind, code, logs, with kind=refused. code is exactly one of input_invalid, policy_mismatch, authority_expired, build_failed, resource_exhausted, output_invalid. No free text or caller echo. These INTERNAL codes map to the existing public authority_unavailable (authority_expired), artifact_rejected (output_invalid) or build_failed (the remaining four); a separately established isolation failure uses existing build_isolation_failed. No new client code or success is manufactured. If cleanup/reap is not established, signer retains its operation gate for reconciliation instead of claiming clean terminal refusal.

logs has exactly stdout, stderr. Each has exactly sha256, bytes, complete: digest of actual retained private stream bytes, canonical byte count, boolean complete. Total retained bytes is overflow-checked against the installed policy's aggregate log-byte budget. Success requires complete=true for both and no exceeded limit. Failure may report a bounded captured prefix with complete=false, never pretend that is a whole log. Empty retained streams use the real SHA256 of empty bytes. These are bounded builder-reported log metadata, not independently verified log content or source authority; private raw logs/paths are not transferred or published by this protocol.

After a successful complete19 control frame, builder streams exactly first.bytes raw bytes, immediately followed by exactly second.bytes, then closes. Each stream has the existing absolute60s budget and the original global600s job budget still caps the exchange. No chunk headers, archive, arbitrary filename/descriptor, extra frame or trailing bytes. Refused19 sends zero artifact bytes then closes. Any malformed/wrong-bound result, missing/short/extra stream, hash mismatch, unequal snapshots or deadline failure withholds signing and cleans only operation-owned partial staging after established cleanup.

## Order and recovery

One connection: authenticated16; then eligible17 or idle20. After17, builder18 is due within5s; then signer sends existing manifest34 and announcement35 plus exact DATA using that job nonce, preserving manifest/DATA bytes. Manifest10s and DATA120s remain separate finite phases inside the unchanged global600s job deadline. Builder validates all input graph, source sums and policy/resource/lease bindings before any compile. No source DATA authority is inferred from registration, acknowledgement or transport hashes alone.

A valid result cannot bypass current authority/admission, required durable intent, native verification or durable outcome. No native key is available to builder. A lost builder response never proves the prior job stopped: before any allowed same-operation re-dispatch, signer must establish prior child cleanup and pre-sign state, use a fresh exchange nonce and remain inside the original finite budget. Unknown cleanup/native state retains uncertainty and the gate; no blind duplicate signing. An ordinary matching client retry only inspects the recorded operation.
